# 知序架构决策记录与渐进式开发计划

- 文档版本：v1.0（2026-10-28 易哥确认）
- 类型：Architecture Decision Records（ADR）+ 实施路线图
- 状态：产品方向已确认；第一项任务 P0-01 已完成（见 baseline-p001.md）

> 本文为原文归档。执行以 P0→P5 阶段推进，未经阶段验收不得进入下一阶段。

## ADR-001：以 Agent 为核心，渐进式演进现有系统（已接受）

保留 React/TS/Vite/Node/SQLite 技术体系与排期算法及测试；业务规则从
HTTP handler 抽离为统一领域服务层；新增 Agent Runtime 通过受控工具
调用业务服务；首页逐步调整为 Agent 对话工作台。

约束：Agent 不得直连 SQLite；不得绕过领域服务改数据；模型输出不得
直接作为已执行的业务事实；不得破坏现有功能。

## ADR-002：当前单用户，预留未来多用户能力（已接受）

暂不建注册/登录/多租户；业务服务避免散落全局单用户假设；禁止客户端
传 user_id 决定权限；监听 0.0.0.0 必须核实网络暴露与访问认证。

## ADR-003：Agent 写操作采用风险分级授权（已接受）

提案→授权→执行三环节；R0 只读自动执行、R1 低风险按策略自动、
R2 中风险默认需确认、R3 高风险必须确认、R4 拒绝或转人工。
确认记录绑定操作内容与版本，实质变化须重新授权。

## ADR-004：排期实时计算 + 有效计划版本 + 关键历史（已接受）

保留纯函数排期算法；业务变更触发计划重算；只有通过约束验证的候选
计划才能成为有效版本；失败结果不得覆盖有效计划；同一时刻仅一个
有效版本。数据实体建议：schedule_versions / schedule_entries /
schedule_changes / schedule_input_revision（以现有表结构为准）。
核验注：scheduleEntries 表已建但从未写入，P3 从零建版本机制。

## ADR-005：模型接入采用可切换适配层，首版只接一种模型（已接受）

统一模型接口；提供方与密钥仅在服务端；统一超时/限流/工具调用处理；
接入前明确数据边界（哪些事务数据可发送、家庭与私人内容过滤）。

## ADR-006：统一执行记录、幂等控制和结果验证（已接受）

执行状态机：proposed → awaiting_confirmation → running → succeeded /
failed / conflicted / cancelled。写工具用幂等键；执行后重读业务数据
验证；区分模型结果、工具结果与数据库最终状态。

## 实施阶段

P0 基础核验与业务服务层 → P1 最小 Agent Runtime 与可靠执行 →
P2 Agent 工作台 → P3 计划版本管理 → P4 后台执行与提醒 → P5 扩展。
P3 数据模型可与 P1 并行，但计划发布机制必须在 Agent 造成复杂排期
变更前可靠运行。

## 贯穿性工程约束

数据库迁移必须有方案与回滚；测试覆盖与风险匹配；可观测性区分业务/
模型/网络/权限错误；不顺便重写无关模块；每阶段输出变更清单、测试
结果、剩余风险与 ADR 符合情况。

## 暂不实施

多 Agent 协作、插件中心、多用户系统、多模型接入、微服务/消息队列、
换数据库/ORM、前端重写、知识图谱/复杂 RAG、无确认自主执行、复杂
主动提醒、删除 taskTemplates/taskFiles 预留表。

## 第一阶段验收场景

“把下周需要完成的某项任务安排到合适时间，如影响其他任务请先告诉我”
——完整走通理解→查询→澄清→候选方案→风险评估→授权→执行→验证→
发布计划版本→记录→展示追溯，并以第五部分十条通过条件为准。

## 补充约束（2026-10-29 外键事实核验，易哥授权更正）

**事实核验**：本项目 SQLite 连接的外键约束**默认启用**——node:sqlite 的
`DatabaseSync` 连接级 `PRAGMA foreign_keys = 1`（P1-03c 数据清理时实测，
删除顺序不当会直接触发 FK 拒绝）。此前「外键仅文档性声明、不生效」的
理解有误。

**后续开发硬约束**（适用于 Agent Runtime 及一切数据库访问路径）：

1. 任何新连接（含测试、脚本、Runtime）必须在初始化时显式验证
   `PRAGMA foreign_keys` 实际状态，不得假设默认值。
2. 外键启用状态下，删除/更新必须遵循既有外键关系与正确顺序
   （先子后父），或依赖已声明的 ON DELETE 行为。
3. 区分三个概念：DDL 中的外键**声明**、连接的**约束开关**、
   运行时**实际行为**——三者不可互相推断。
4. 新增 DDL 的结构自检沿用 P1-03b 模式（sqlite_master 文本归一化比对）。
